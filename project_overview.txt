3. CORE ALGORITHM & ROUTING LOGIC
------------------------------------------------------------------------
- Graph Construction: `buildGraph()` reads lines configuration and builds a standard adjacency list map representation `Record<string, GraphEdge[]>`, where each edge contains target `stationId` and `lineId`.
- Pathfinder: `findRoute()` runs a Breadth-First Search (BFS) to find the shortest path (minimum stops). 
  - To handle multiple routes with the same number of stops, it uses a tie-breaker prioritizing the path with the fewest line interchanges (transfers).
  - It breaks the final path into distinct segments, each detailing the line used and stations visited, and identifies transfer stations (e.g. Sadat, Attaba, Al-Shohadaa).
- Ticket Fare: Computes ticket prices based on the number of traversed stations:
  - 1 to 9 stops = 9 EGP
  - 10 to 16 stops = 12 EGP
  - 17 or more stops = 15 EGP
- Estimated Time: Estimations are calculated as:
  - (number of stops * 2 minutes) + (number of line interchanges * 4 minutes)

4. DESIGN AESTHETICS & ACCESSIBILITY
------------------------------------------------------------------------
- Brand Palette (Official Cairo Metro stars emblem):
  - Metro Red (#C01010): Primary accent, Line 1, M Logo, buttons.
  - Steel Blue (#0050A0): Secondary accent, Line 2, panel borders.
  - Mid Blue (#3070A0): Tertiary accent, Line 3, history log indicator.
  - Sand (#C0A080): Header backgrounds and field borders.
  - Off-White (#F0F0F0): Light-themed container background.
- Background Pattern: A custom CSS repeating rub-el-hizb (8-pointed star) background motif styled in Tailwind utility classes (`star-pattern`).
- Bilingual Layout: The UI dynamically switches between LTR (English) and RTL (Arabic) with correct layout alignment, directionality (`dir="rtl"`), and mirrored icons (e.g. swap arrow, timeline nodes).
- Accessibility (A11y): Autocomplete pickers support full keyboard navigation (Up/Down to navigate, Enter to choose, Escape to close, Screen Reader instructions, and ARIA attributes like `aria-expanded`, `aria-selected`, and `role="listbox"/"option"`).

5. TESTING STRATEGY
------------------------------------------------------------------------
- Unit & Component Testing: Vitest executes 16 test cases covering BFS routing, fare brackets, time estimations, and integration rendering flows. Map dependencies are mocked for tests to isolate DOM rendering from WebGL rendering errors.
- End-to-End Testing: Playwright launches the Vite dev server and triggers a real Chromium session. It simulates a user selecting Helwan and Maadi, swapping directions, checking stats updates, and toggling Arabic translations.
